# 上下文、文风与宿主

## 长篇怎么记住前文

500 章以上不把全文塞进窗口。近处用章摘要，中距离用弧摘要，远处用卷摘要。

```text
卷摘要
  └── 弧摘要 + 角色快照 + 这一弧的写作规则
        └── 最近若干章摘要（窗口见领域文档里的上下文策略）
```

写每一章时另外准备三样东西：

- 相关历史章：伏笔、出场、状态变化、关系四个维度反查，只给章节号和理由，正文由写作者按需 `read_chapter`。
- 下一章大纲：用来设计章末钩子，不把下一章写成这一章。
- 弧或卷的边界事实：提交结果里会有，`Route` 以文件为准再派审阅、摘要或展开。

初始规划只生成终局方向、起步两卷、第 1 弧的详细章节、角色和世界规则。卷写完后，长篇规划师按已写内容决定追加、收官或完本。指南针（终局方向、活跃长线、规模估计）在卷边界更新，方向可以随正文演化。

骨架弧只有目标和预估章数。展开时同步修订下一骨架弧的标题和目标，已写章节不动。

## 上下文压缩

对话超出当前模型窗口时，按代价从低到高：

```text
清掉过旧的工具结果
  → 截断过长文本
  → 用文件里已有的章摘要、角色快照、伏笔台账替换旧消息（不调用模型）
  → 最后才用模型做叙事摘要
```

写作者的模型摘要必须保留：角色状态、未收伏笔、审稿待修、文风锚点。摘要替换之后，再注入当前章计划、本章大纲和角色快照，避免压缩后失忆。

压缩连续失败则跳过并明确告警，下一轮再试。中文长度按字符数估算，不用“字节除以 4”，避免窗口已经满了还没触发压缩。

观察层可以显示占用：低于 70% 正常，70% 到 85% 警告，高于 85% 危险。显示不参与控制。

## 文风

协议和文风分开。`writer.md` 里的 `{{VOICE}}` 原位替换为文风文本，再接上风格预设。生产、评测、测试走同一个组装函数。

覆盖从低到高：

| 资产 | 规则 |
|---|---|
| `voice.md`、去 AI 腔参考 | 内置保留。全局和本书以带标题的段落追加。后写的优先是给模型的指示，不是机械覆盖 |
| `styles/<名字>.md` | 同名整文件替换。新文件名就是新风格。本书没有对应参考时不回退默认风格 |
| 用户规则 | 运行时最高优先级，来自裁定的 `rules` |

路径：

```text
本书 <书目录>/style/    优先于    全局 ~/.ainovel/style/    优先于    包内 ainovel/assets/
```

本书级绑定这本书的目录，不绑定进程的当前工作目录。需要机械保证的禁用词、疲劳词、字数，走规则层，在提交时检查，并出现在 `commit_chapter` 的 `rule_violations` 里。

## 风格统计

每本书一份索引。首次启动从全部已完成章重建，之后对新增和重写增量更新：句式、高频短语、跨章重复句、章末形态。`novel_context` 把统计注入给写作者避开口头禅，注入给审阅者对照数字。统计由代码计算，好不好由模型判断。索引与 `commit_chapter` 共享同一对象，恢复提交完成后也要刷新。

## 章节推进门

这是引擎边界上的政策，不进 `Route`，不进工具。它执行用户事先签下的两种意图：

| 意图 | 来源 | 语义 |
|---|---|---|
| `advance_mode=review` 加上精确的 `advance_permit_chapter` | 打开逐章验收、放行下一章 | 持久政策。每个正向新章单独放行 |
| `advance_hold` | 干预裁定 | 一次性。到达边界、返工排空，或目标章稳定提交后暂停 |

只拦截“再写一个新章”。返工、审阅、结构维护、提交恢复都不拦截。

许可绑定章节号。只有该章进入已完成列表、`pending_commit` 已清除、并且存在这次提交的检查点，才消费许可。提交中途崩溃不会把同一许可用到下一章。`auto` 模式下如果还留着许可章号，视为损坏，暂停并说明，不猜测。

## 宿主

宿主拥有一本书的租约：先独占目录，再打开日志，再装配存储、模型和引擎。这样日志能盖住装配失败，也不会两进程同时写一本书。

生命周期：

- `start`：新需求。写 `start_prompt`，做启动裁定，拉起引擎。
- `resume`：进程重启。先处理 `pending_steer` 和未完成提交，再按文件续跑。
- `continue`：用户明确要求从空闲或暂停继续。
- `steer`：写入干预并裁定。
- `abort`：取消当前循环。已落盘步骤保留。
- `close`：释放目录租约。

对外只暴露事件流和快照。快照包括阶段、流程、当前章、最近一条指令、上下文占用、是否暂停。界面和日志是事件的投影。错误的完整文本进日志；界面只显示短摘要，并按宽度截断。成功生成的正文留在书籍目录和会话工件里，不把全文再抄进运行日志。

预算在每轮边界检查。超预算暂停，不在工具里偷偷停。

完本后的报告由宿主用已有事实渲染：章数、字数、卷弧、未收伏笔应已为空。不为此再调用模型。

## 无界面命令

第一版只有无界面入口，适合在服务器上一直跑。斜线命令可以是启动参数，也可以是运行中的一行输入：

| 命令 | 作用 |
|---|---|
| 启动时的需求文本 | 新书，或附加到已有书的继续 |
| `/steer <文本>` | 注入修改意见，不要求先暂停 |
| `/review on` `/review off` | 切换逐章验收与自动推进 |
| `/next` | 在逐章验收下，放行下一个新章 |
| 暂停 / 继续 | 取消循环，或从最近事实再启动 |
| 换模型 | 更换角色模型。写作者的上下文窗口随模型重建 |

`/review on` 之后，`/next` 只放行一个新章。返工和崩溃恢复不消耗这张许可。

配置放在用户目录 `~/.ainovel/`：提供方密钥、默认模型、角色模型、全局文风。无界面模式不走首次向导；缺配置时直接失败并指出缺什么。向导留给后置的终端界面。

Headless 的最小闭环是：给定书目录和一句话，引擎能规划、写出至少一章、在弧末停在正确的下一指令上；中途杀掉进程再启动，不重写已提交的章。
