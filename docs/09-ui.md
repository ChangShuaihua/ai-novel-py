# 界面

React 写作控制室。它是 `entry` 的另一种投影：展示宿主快照和短事件，接收用户意图，把意图交给已有的宿主动作。规格在这里写清。界面工程在 `web/`，由 `python -m ainovel.entry.headless web` 在本机打开。本地通道的路径、端口和报文不在这篇里设计。

界面遵守 [架构铁律](01-architecture.md) 第 7 条：不直接读存储，只订阅宿主事件或读宿主快照。工具、路由和提交 Saga 仍由引擎持有。

## 边界

- 进度、阶段、流程、许可和暂停原因只来自快照。事件是短摘要。界面不从事件文本重建进度，也不把成功生成的正文抄进事件列表。正文留在书籍目录里，阅读视图使用宿主给出的只读投影。
- 每个控件只对应一个已有宿主动作：`start`、`resume`、`steer`、`abort`、`review on`、`review off`、`next`、导入确认、`export`、`diag`。界面不调用工具，不改 `Route`。
- 章节阅读只读，顺序与 `completed_chapters` 一致。改剧情只通过干预文本。
- 一本书一个串行引擎。目录被占用时只显示锁，不并行启动第二本的写作。
- 缺少可用的模型配置时，需要模型的动作不可用。接入在「接入模型」里完成，写入 `~/.ainovel/config.json`。界面不回显完整密钥；密钥留空表示保持已保存的值。
- 错误的完整文本留在日志。界面只显示宿主给出的短摘要。
- 完本报告使用宿主已渲染的章数、字数、卷、弧和未收伏笔。界面不为报告再请求模型。
- 引擎停住之后不会自己续跑。再次写作只来自用户按下的继续、放行或新的干预。

## 屏幕

```text
书架
  ├─ 接入模型
  ├─ 新书
  └─ 写作现场
       ├─ 章节阅读
       ├─ 导入确认
       ├─ 诊断与导出
       └─ 投稿资料
```

一屏回答三件事：这本书现在在哪，下一步谁能动，当前能发哪一个意图。正文用阅读排版。事件用短行列表。两者分开，不混成一条滚动日志。

### 书架

本机书目录的列表。每本显示书名、阶段、已完成章数、是否被占用。已知总章数时，章列写成「已完成/总章数」，书名下有一条同比例的细线。

空列表提供「新建」。点进一本未被占用的书，进入写作现场。尚未出现在书架上的书，用本机目录选择打开，不手填路径。被占用的书可以看快照，启动、恢复和干预不可用，并显示锁所在的 `.ainovel.lock`。

书架不扫描章节正文，不自己累加字数。书名和章数都来自每本书的快照。

### 接入模型

顶栏随时可以进入。提供方和模型从列表里选，不用手填。密钥、接口地址和文风仍可填写。保存后写入 `~/.ainovel/config.json`。命令行读的是同一份文件。已经保存、但不在列表里的名字仍留在选项里。

页面只显示密钥是否已保存，以及不少于 8 位时的末四位。留空保存保持原密钥。勾选清除才会把密钥写成空，之后由调用层按该提供方的环境变量取密钥。接口地址留空则不传入。文风留空表示不附加预设。

当前有一轮写作在跑时，保存对这一轮不生效，结束后的下一轮才换上。文件里已有的其他字段保持不动。

### 新书

一个需求输入框，提交后调用 `start`。目录用本机选择；不选则由书架新建一个目录。

已有进度的目录不进入这个屏幕。继续那本书用写作现场的「继续」，对应 `resume`。`start` 会把进度写成 `init` 并清空检查点，所以它只出现在新书。

### 写作现场

主屏幕。

```text
顶栏    书名 · 阶段 · 流程 · 自动推进或逐章验收
进度    阶段轨 · 已完成章数/总章数 · 章格或比例条
中部    当前状态短句 · 最近一条指令 · 最近章节摘录 · 事件短列表
侧栏    下一章 · 返工队列 · 暂停原因 · 上下文占用 · 完本报告
底部    干预输入
```

顶栏的推进方式来自 `advance_mode`：`auto` 显示自动推进，`review` 显示逐章验收。切换对应 `review off` 与 `review on`。切回自动推进只改模式，不隐式启动已经暂停的引擎。

进度条只读快照。阶段轨按 `init`、`premise`、`outline`、`writing`、`complete` 排列，当前位置来自 `phase`。章进度用 `completed_chapters` 和 `total_chapters`：36 章及以内逐格标出已完成、待返工和正在写的下一章；更多时改成一条比例。字数用 `total_word_count`，为 0 时不显示。界面不从大纲文件或事件补章数。

中部的最近章节摘录是宿主截断后的只读文本，取自 `completed_chapters` 的最后一章。没有已完成章节时，中部只显示当前状态和事件。事件按时间排列，新的在下。界面按宽度截断每一行，不展开错误全文。

侧栏：

- 下一章来自快照的 `next_chapter`。
- 返工队列来自 `pending_rewrites`，队首在前。
- 暂停原因来自快照的 `pause_reason`；存在 `advance_hold` 时同时显示 `after` 与 `reason`。
- 上下文占用由宿主在轮次边界填入。宿主尚未给出时，这一行留空。界面不自己估算 token。
- 阶段为 `complete` 时，侧栏展示完本报告。

底部干预框在引擎运行或暂停时都可提交，对应 `steer`。裁定的回显作为一条短事件出现。`pending_steer` 非空时，输入框显示这份尚未处理完的文本，恢复后由宿主重放，界面不另发一次。

引擎正在运行时，顶栏提供「暂停」，对应 `abort`。它取消当前循环，已落盘的步骤保留。暂停后的继续对应 `resume`。

主按钮随下面的状态表切换，同一时刻只有一个。完本、配置缺失和目录占用不显示主按钮。

「放行下一章」只在状态表的「等待放行」成立时可用。返工进行中、引擎正在跑、存在 `advance_hold`，或许可已经发给某一章时，这个按钮不可用。许可在该章稳定提交后由引擎消费；界面不提前把它挪到下一章。

等待放行时，状态短句沿用引擎已有的说法：规划刚就绪时是「规划已就绪，逐章验收等待放行第 N 章」；已有完成章时是「已完成至第 M 章，逐章验收等待放行第 N 章」。用户仍可以在这个状态发送干预。

### 章节阅读

只读。章节顺序与 `completed_chapters` 一致，可以和文件名的数字顺序不同。每章显示章节号、标题和正文。没有保存，没有改字，没有重排。

标题和正文来自宿主的章节投影。投影缺失某一章时，该章显示「正文缺失」，不把进度改回未完成。

### 导入确认

从写作现场进入。界面展示宿主返回的章节标题列表，以及当前导入状态。

| 宿主状态 | 屏幕 | 主操作 |
|---|---|---|
| 待确认切分 | 标题列表，等待用户看过 | 确认切分 |
| 确认之后的分析、合成或发布仍在进行 | 已确认的标题，加上短状态 | 无新的主操作 |
| 已发布并停在边界 | 说明导入已发布，写作尚未继续 | 回到写作现场后按「继续」 |

确认切分只接受当前这份已校验的切分，不要求模型重新切章。发布前的正文不出现在章节阅读里。切分失败时，屏幕显示宿主给出的短摘要；原始响应仍留在导入工作区，由诊断或日志查看，界面不直接打开那个文件。

### 诊断与导出

诊断列出宿主返回的发现：缺章、规则问题、检查点骨架里的序号、步骤、范围和章节号。骨架不带正文。诊断屏幕没有「修好它」或「继续写」按钮。

导出收集一个本机目标路径。宿主按 `completed_chapters` 写出 TXT。界面显示写出的路径。界面不在浏览器里拼接章节正文。保存位置用本机保存对话框选择。

### 投稿资料

只读。从书名、简介、人物和前提生成创建作品要填的几项：书名不超过 15 字，主角名最多两个、每个不超过 5 字，简介压在 50 到 500 字，并给出目标读者和一对标签建议。另有一条封面生图提示词：竖版、一个主角、书名留白，道具和气质来自这本书。界面可以复制每一项。这里不改书，不调用写作循环。简介里的人名和人物表主角对不上时，显示一句提示。

## 快照

写作现场和书架渲染同一份快照。界面不另建一份进度。

| 字段 | 来源 | 界面用途 |
|---|---|---|
| `title` | 作品信息 | 书架和顶栏 |
| `phase` | 进度 | 阶段 |
| `flow` | 进度 | 流程；空则不显示流程标签 |
| `current_chapter` | 进度 | 当前章 |
| `next_chapter` | 进度 | 侧栏下一章，也是放行目标 |
| `completed_chapters` | 进度 | 章数和阅读顺序 |
| `total_chapters` | 进度 | 总章数；0 表示还没定 |
| `total_word_count` | 进度 | 完本报告中的字数 |
| `pending_rewrites` | 进度 | 返工队列 |
| `latest_instruction` | 引擎最近一条指令的任务与原因 | 中部「最近一条指令」 |
| `running` | 引擎是否在跑 | 区分暂停与写作中 |
| `paused` | 引擎是否已暂停 | 主按钮是否为继续 |
| `pause_reason` | 引擎暂停原因 | 侧栏与状态短句 |
| `advance_mode` | `run.json` | 自动推进或逐章验收 |
| `advance_permit_chapter` | `run.json` | 已放行的章节；0 表示没有许可 |
| `advance_hold` | `run.json` | `after`、`target_chapter`、`reason` |
| `pending_steer` | `run.json` | 恢复前要重放的干预 |
| `context_usage` | 宿主在轮次边界填入 | 侧栏占用；缺省则留空 |
| `report` | 完本报告 | 仅 `phase=complete` 时展示 |
| `events` | 宿主短事件 | 中部列表 |
| `locked` | 目录租约 | 书架上的占用 |
| `config_ready` | 用户目录里是否有可用的模型配置 | 挡住需要模型的动作 |
| `chapters` | 宿主只读投影，元素为章节号、标题、正文 | 阅读视图和最近摘录 |
| `import_status` | 导入工作区的下一步 | 导入确认屏 |
| `import_chapters` | 已识别的章节标题 | 导入确认屏 |
| `findings` | 诊断结果 | 诊断屏 |

`chapters` 的顺序与 `completed_chapters` 相同。界面拿到投影后直接渲染，不按文件名再排序，也不去读 `chapters/`。

## 状态

同一时刻取表中第一条匹配的状态。前面的状态挡住后面的主操作。错误短摘要叠在命中的状态上。

| 状态 | 何时显示 | 主操作 | 同时不可用 |
|---|---|---|---|
| 配置缺失 | `config_ready` 为假 | 无。句子指向接入模型 | `start`、`resume`、`steer`、`next`、导入确认 |
| 目录占用 | `locked` 为真 | 无。显示锁 | `start`、`resume`、`steer`、`abort`、`next` |
| 导入待确认 | `import_status` 为待确认 | 确认切分 | `next` |
| 完本 | `phase` 为 `complete` | 无。展示 `report`，可进入阅读 | `start`、`next` |
| 返工中 | `pending_rewrites` 非空 | 引擎在跑时为发送干预，未跑时为继续 | `next` |
| 等待放行 | 模式为 `review`，`phase` 为 `writing`，引擎未跑，许可为 0，没有 `advance_hold`，返工队列为空 | 放行下一章 | 无 |
| 边界暂停 | `paused` 为真，且仍有 `advance_hold` | 继续 | `next` |
| 规划中 | `phase` 为 `init`、`premise` 或 `outline` | 引擎在跑时为发送干预，未跑时为继续 | `next` |
| 自动写作 | 模式为 `auto`，`phase` 为 `writing`，引擎在跑 | 发送干预 | `next` |
| 写作中 | `phase` 为 `writing`，引擎在跑 | 发送干预 | `next` |
| 待继续 | 引擎未跑，阶段尚未完本 | 继续 | `next` |

宿主错误作为短摘要叠在当前状态上，不改上表的主按钮。这次失败停在原处，用户可以再次发送同一个意图。

诊断与导出在配置缺失和目录占用时仍可打开。它们只读，不需要模型和写租约。

暂停原因沿用引擎原文，显示在侧栏。返工排空是「返工队列已排空，已暂停等待验收」。写到指定章是「已写到第 N 章，按用户要求暂停」。其余边界是「已按用户要求在当前工作边界暂停」。宿主带了诉求时，短句后面附上原因。返工排空时一次性暂停已经清掉，若此时满足「等待放行」，主按钮是放行下一章，短句仍留在侧栏。

## 明确不做

- 不在浏览器里编辑章节、大纲、角色或世界规则。
- 不在界面里选择下一步派谁，也不提供第二个开始循环的按钮。
- 不把逐章验收扩展成逐步确认规划、审阅和摘要。
- 不预授权多章，不做许可队列。
- 不在界面回显完整密钥，也不在界面里改某一轮已经打开的模型。
- 不把事件列表当成正文归档。
